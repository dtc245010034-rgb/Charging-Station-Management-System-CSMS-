## 1. Requirement & Acceptance Criteria

### S-03
Mỗi vai trò chỉ thấy và thao tác được phần việc của mình: Thiết lập ma trận phân quyền tập trung (RBAC), thực thi nguyên tắc phòng thủ Default Deny (mọi route chưa khai báo quyền đều bị chặn HTTP 403), và bảo đảm cô lập dữ liệu theo quyền sở hữu (Ownership Isolation) tại tầng truy vấn cơ sở dữ liệu.

#### Acceptance Criteria
- **S03-AC-01**: Owner A mở danh sách station -> chỉ thấy station của A. Owner B -> chỉ thấy B. Phải xác minh API và data layer.
- **S03-AC-02**: Người dùng gọi API vượt quá thẩm quyền của vai trò (ví dụ DRIVER gọi API tạo trạm) -> HTTP 403.
- **S03-AC-03**: Đăng ký công khai không được tự gán vai trò quản trị (chặn leo quyền) -> HTTP 400.
- **S03-AC-04**: Route chưa khai permission -> mọi vai trò gọi route đó đều nhận HTTP 403 (Default Deny).

#### Non-functional Requirements
- **S03-NFR-01**: Ownership filtering: phải nằm ở query/data access layer (`WHERE s.owner_id = ?`). Không chấp nhận lọc chỉ ở giao diện.

## 2. Tasks Liên Kết

### T-06 — Ma trận phân quyền RBAC và cơ chế phòng thủ Default Deny
- **T06-01**: Bảng ma trận quyền tập trung gán quyền hạn chi tiết cho từng vai trò.
- **T06-02**: Route Guard chặn mặc định (Default Deny) mọi route chưa đăng ký quyền hạn.
- **T06-03**: Cấm sử dụng trực tiếp `express.Router()` trong thư mục `modules/` (ràng buộc qua ESLint rule `no-restricted-syntax`).

### T-07 — Cô lập dữ liệu trạm sạc theo chủ sở hữu (Ownership Scoping)
- **T07-01**: Hàm tập trung `scopeByOwner` tự động gắn điều kiện lọc `owner_id` vào câu lệnh SQL khi vai trò là `STATION_OWNER`.
- **T07-02**: Vai trò quản trị toàn hệ thống (`ADMIN`, `OPERATOR`) không bị lọc dữ liệu theo chủ sở hữu.
- **T07-03**: Bảo vệ chống SQL Injection qua tên bảng hoặc alias trong helper truy vấn.
