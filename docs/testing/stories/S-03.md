## 1. Requirement & Acceptance Criteria

### S-03
Mỗi vai trò chỉ thấy và thao tác được phần việc của mình: Thiết lập ma trận phân quyền tập trung (RBAC), thực thi nguyên tắc phòng thủ Default Deny (mọi route chưa khai báo quyền đều bị chặn HTTP 403), và bảo đảm cô lập dữ liệu theo quyền sở hữu (Ownership Isolation) tại tầng truy vấn cơ sở dữ liệu.

#### Acceptance Criteria
- **S03-AC-01**: Owner A mở danh sách station -> chỉ thấy station của A. Owner B -> chỉ thấy B. Không chỉ kiểm tra UI, phải xác minh API/data layer.
- **S03-AC-02**: Owner A gọi trực tiếp API/resource của Owner B bằng curl -> HTTP 403 và audit/security log được ghi nhận trong cơ sở dữ liệu.
- **S03-AC-03**: DRIVER gọi API dành cho OPERATOR -> HTTP 403.
- **S03-AC-04**: Route chưa khai permission -> ADMIN gọi route đó vẫn nhận HTTP 403 (Default Deny). (Nếu không có route/test phù hợp: NOT VERIFIED. Không tự thêm route để test).

#### Non-functional Requirements
- **S03-NFR-01**: Ownership filtering: phải nằm ở query/data access layer (`WHERE s.owner_id = ?`). Không chấp nhận frontend-only filtering.

---

## 2. Tasks Scope

### T-06 — Middleware kiểm role, default deny
- **T06-01**: Route chưa khai quyền -> ADMIN -> HTTP 403.
- **T06-02**: Route có khai quyền -> correct role allowed, wrong role 403. Centralized middleware, route guard, permission matrix.

### T-07 — Ownership query + curl 403
- **T07-01**: Owner A -> resource của B -> 403.
- **T07-02**: Security/audit log: có log cho unauthorized ownership access (`ACCESS_DENIED`).
- **T07-03**: Automated test: backend tests có kịch bản Owner A gọi resource B -> 403.
- **T07-NFR**: Ownership condition phải dùng shared function duy nhất (`scopeByOwner`). Không copy/paste thủ công ở từng query.
